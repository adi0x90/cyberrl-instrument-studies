 Title: Auditing Reward Hackability in Code RL Training Environments

 Authors: Shreshth Rajan 
 View a PDF of the paper titled Auditing Reward Hackability in Code RL Training Environments, by Shreshth Rajan

 View PDF 
 HTML (experimental) 

 Abstract: Code RL rewards a policy for passing a task's tests, so a test suite that accepts a wrong patch trains the wrong behavior. We measure how often open code RL environments accept wrong patches and how reliably hackable tasks can be detected and repaired, checking each claim by execution against the task's gold patch. First, 22.4% of 49 SWE-bench Verified tasks accept a Docker-verified patch that behaves differently from the gold patch, and 57.8% against a stronger attacker. The gold-patch check is necessary: an attacker not shown the gold patch returns it for 31% of its passing "exploits". Second, across 134 public SWE-bench submissions, models pass hackable tasks 28.6 pp more often than tasks of the same difficulty, mostly because those tasks are passable at all; pooled over three attacker runs, hackable tasks still exceed matched passable ones (p=0.014). Third, repair is harder to verify than detection: 61.9% of LLM-written repair tests fail on the gold patch, and even behind a gate an LLM judge is wrong on 38% of the verdicts execution can check. Finally, of 873 training trajectories behind an open coding agent run beside the gold fix, 19.4% answer differently on a case the issue describes; an LLM review that can only demote these executed differences judges 6.9% to be wrong fixes the tests rewarded (6.4-10.5% across three model reviews), and 5.4% in a second public training set (R2E-Gym). End to end, the gated repair yields verified tests for 290 of 324 wrong fixes in that agent's data and all 9 in 384 rewarded Open-SWE-Traces rollouts (2.3%). One-shot attacks hack 23 of 100 SWE-bench Pro V2 and 9 of 112 DeepSWE tasks; 12 of 1,344 passing DeepSWE leaderboard patches are model-judged wrong. Science graders mostly hold: an agentic red team passes 0 of 61 Terminal-Bench-Science tasks. Audits and repairs of code RL environments should be decided by execution wherever execution can decide.
