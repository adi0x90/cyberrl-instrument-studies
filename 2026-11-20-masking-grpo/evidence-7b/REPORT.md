## 7. Seeds — per-seed rows and the pooled estimate

Seed runs are detected from the metrics files: the flat `*_<arm>` set is one run, and each `seed<number>/` subdirectory (or `*_<arm>_<number>` suffix) is another. Per-seed rows are printed next to the pooled row. A pooled proportion **sums draws**; it never averages per-seed rates. Pooling does not create replication: seeds are few, and the counts are not equal across arms (the v1 seed covers control and masked only), so the pooled interval is a binomial interval on the pooled draws, not a seed-level variance estimate.


Pooled rows sum each arm's runs that exist; an arm with fewer seeds has fewer draws in its pooled row, which is why the draw counts are printed rather than assumed equal.

## What this does not show

- **It does not establish equivalence when the verdict is 'no measurable difference'.** The rule can only fire on a large gap: with 64 draws per arm under Amendment v2 (32 under v1), two intervals overlap for any moderate difference, so the binding constraint is non-overlap, not the 12-point threshold. A null here is 'this design could not see it at this n', not 'the treatments are the same'.
- **It is not a capability claim.** Eight train tasks, four held-out tasks and a 1.5B policy measure whether a baseline treatment changes the gradient, not how good the model is. A null on held-out success does not refute the mechanism, and a win on held-out success would not generalise past this corpus.
- **Few seeds, and not equal across arms.** Amendment v2 adds one seed for all three arms on top of the v1 seed, which covers control and masked only. The pooled row sums draws and is reported alongside the per-seed rows; it is not a hierarchical model and it does not turn draws into independent replication. The paired per-group variance comparison is within-run and paired on prompts only.
- **The effective-update counts are not a Bernoulli sample.** The policy changes after every effective update, so successive groups are not i.i.d.; the Wilson interval on the effective-group rate is descriptive, not a confidence statement about a population.
- **Budget parity is on effective steps, not compute.** Every arm is asked for the same target number of effective updates under the same group cap (24/96 in the original protocol, 8/40 after the v1 deviation; the manifest records which), but the arms spend different numbers of rollouts to get there. The cost ratio is reported rather than equalised, so a cheap arm and an expensive arm are not compared at equal compute.
- **Admission is reported separately from HOLDS for a reason.** A model can learn the strict JSON envelope without learning the repair, and that would show up as a held-out admission win with no joint-success win. Neither endpoint alone identifies which happened.
- **The penalty arm changes one number, not the whole reward.** A rejected completion is worth −1.0 instead of 0.0; a rejected action and a wrong-but-valid repair are otherwise scored by the same rules. A difference between penalty and control is a difference in the valuation of format failure, not a different task or a different grader.
- **No PPO clipping, no KL term.** The importance ratio is 1 by construction (one step per group), so this isolates the baseline treatment; it is not a full GRPO recipe and its numbers should not be compared with one.
- **`HOLDS` means 'not caught by this grader', not 'correct'.** The obligation grader is a program with its own blind spots; it rejects security failures, benign-behaviour loss, no-ops, trivial wrappers and out-of-scope names, and nothing else.
- **The final update only is evaluated.** There is no checkpoint selection by design, so a transient improvement earlier in a run is invisible, and a late collapse is fully weighted.
- **Format learning and repair learning are not separated within a run.** The train-side admission and joint-success rates move together when the model first learns the envelope; the report cannot attribute a mid-run jump to either.
